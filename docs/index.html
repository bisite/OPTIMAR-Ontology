Introduction back to ToC

The OPTiMAR ontology provides a shared vocabulary for the operation and maintenance (O&M) of floating offshore wind platforms. It was developed in the OPTiMAR project following the LOT methodology, from requirements elicited with industrial partners and formalised as competency questions.

The ontology is organised in the following modules:

  • Assets: wind farms, platforms, turbine components (blade, hub, nacelle, tower), drivetrain and electrical components, the floating substructure and its members (columns, heave plates, braces), and the mooring system (lines, anchors, connectors, tensioners, fairleads) with its classification by configuration and duration.
  • Site: location, water depth and seabed characteristics.
  • Sensing: sensor types, the components they are installed in or monitor, the data they produce, and their sampling frequency and data format. Observations follow the SOSA pattern (sosa:madeBySensor, sosa:hasFeatureOfInterest, sosa:hasResult).
  • Failures and events: failure types, failure events, and their links to affected components, environmental causes and evidencing observations.
  • Operations: actors, roles, tasks and maintenance activities, aligned with PROV-O (prov:Agent, prov:Activity, prov:wasAssociatedWith).

Quantities are expressed as qudt:QuantityValue instances with QUDT units. Alignments with SAREF and the Open Energy Ontology are published as a separate module (ontology/alignments).

The GitHub repository contains the example instantiation, the competency questions as SPARQL queries with a script to run them, the changelog, and contribution guidelines. Issues and change requests can be submitted through GitHub issues.
